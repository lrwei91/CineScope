# CineScope 视觉改版简报

## 目标与范围

- 目标用户：需要快速浏览近期影视、按条件筛选并查看详情的中文用户。
- 首要任务：先确认当前片单和分类，再通过搜索、评分、类型筛选定位作品，并打开详情或预告片。
- 本次范围：首页的桌面端、移动端、作品详情抽屉、预告片弹层和分享入口的视觉与交互一致性。
- 非目标：不改变静态站点、JSON 数据、数据生成流程、豆瓣同步机制或现有分类路由。

## 现状依据

- 运行态页面的首屏同时承载终端式 Hero、三组筛选和年份浮层，视觉焦点分散。
- index.html、style.css 与 js/modules/renderer.js 显示筛选、卡片和时间线使用了不一致的交互语义；卡片原先只支持鼠标点击。
- 设计以项目真实片单、同步状态和预告片为内容依据；未采用外部图片、品牌、评价或第三方设计参考。

## 视觉方向

一句话主张：以深色电影编辑台呈现动态片单，让内容、筛选结果和作品信息成为唯一主角。

- 不采用 project-standards 的可选主题配方；使用项目内新的中性语义 token。
- 深色画布、暖琥珀强调色、衬线标题和无衬线正文建立“影视编辑”语境。
- 强调色只用于已选筛选、可操作入口和高价值数值；同步、警告、收藏状态使用独立语义色。
- 移除扫描线、霓虹、故障字、无目的卡片 3D 和打字机状态效果。

## 信息与交互规则

- 首屏按“片单身份 → 更新时间/同步状态 → 搜索与筛选 → 结果”组织。
- 搜索、分类、评分和类型是高频动作，桌面端直接可见；手机端以分类面板和底部筛选面板承载。
- 作品卡片使用明确的详情按钮语义；预告片是独立按钮，避免嵌套交互控件。
- 筛选标签使用原生按钮和 aria-pressed 表达选择状态；年份跳转使用原生按钮和当前项标记。
- 详情、预告片和手机面板以 dialog 语义打开，接收焦点、支持 Tab 循环与 Escape 关闭，并在关闭后返回原触发点。

## 响应式与验收

- 1440/1024px：内容驱动卡片网格，左侧年份工具仅在空间充足时显示。
- 768px：筛选区域开始切换为移动工作流，避免压缩桌面控件。
- 390px：等权且短内容的作品卡片使用双列；筛选操作进入底部面板。
- 320px：作品卡片切为单列，保证标题、状态和操作不被压缩。
- 减弱动效模式下，页面不使用平滑滚动、卡片位移或持续骨架动画作为理解和操作前置条件。

验证覆盖：npm run check、npm run build:site，以及本地浏览器 320、390、768、1024、1440px 的首页、筛选、详情、预告片、键盘和减弱动效检查。
